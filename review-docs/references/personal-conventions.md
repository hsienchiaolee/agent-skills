# Personal conventions

These are the skill owner's defaults, not universal technical-writing standards. Explicit user
instructions and applicable project conventions take precedence. Apply them in proportion to the
review scope and label preference-only suggestions separately from material findings.
Personal preference differences alone do not justify a changes-requested verdict unless the user
or project has made them requirements.

- Durable documentation should be self-explanatory for its intended audience. Include the context,
  decisions, and rationale readers need without assuming familiarity with project conversations
  or requiring them to reconstruct that context from Slack, tickets, or task history. Links to
  official documentation and other canonical references are welcome; do not duplicate those
  sources merely to make a document self-contained. Keep execution and closeout narration out of
  durable documentation while preserving material rationale, confirmation, and technical evidence.
- Target 100-column Markdown prose, allowing necessary code, URLs, and tables to exceed it. Prefer
  reference links for long destinations and inline links for short ones. This target alone does
  not justify a finding or rewrapping churn.

# Guidance sources

Consult the relevant source when a concrete review question needs clarification. These links are
not a required research checklist. User instructions and project conventions take precedence;
Google style is the preferred fallback, applied according to reader impact.

- [Google documentation best practices](https://google.github.io/styleguide/docguide/best_practices.html): maintenance, ownership, and duplication.
- [Google tables](https://developers.google.com/style/tables): comparison, headers, and readable cells.
- [Google procedures](https://developers.google.com/style/procedures): usable task instructions.
- [Google accessibility](https://developers.google.com/style/accessibility): accessible text and structure.
- [Google terminology](https://developers.google.com/tech-writing/one/words): consistent terms and clear references.
- [Google timeless documentation](https://developers.google.com/style/timeless-documentation): time-relative language in maintained guides.
- [Diátaxis purposes](https://diataxis.fr/start-here/) and [pragmatic application](https://diataxis.fr/how-to-use-diataxis/): audience and purpose, without mandatory repository structure.
- [Architecture decision records](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions.html): decision context, status, and consequences.

These resources were identified in the supplied researched guidance, dated September 22, 2026.
That provenance is not a claim that this skill's creation rechecked every linked page, nor a
verification date for documentation reviewed with this skill. Personal conventions are maintained
separately in [personal-conventions.md](personal-conventions.md).
